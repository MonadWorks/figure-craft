# Template Map

The bundle contains real paper figure families. Use them as optional visual references and renderer examples, not as an obligatory starting point. A reference is useful only when it saves work without distorting the scientific question; a figure can equally well be designed from scratch.

## Examples by evidence structure

| Evidence shape | Optional reference | Possible idea to borrow | Usually change |
|---|---|---|---|
| Protocol, model, stimulus, readout, or one illustrative instance | `templates/icbr/fig1_data_overview` or the graphical abstract | left-to-right evidence story, schematic/data separation, icon scale | scientific objects, labels, number of steps, source-backed relationships |
| Paired method comparison with distributions and an aggregate effect | `templates/icbr/fig2_recording_decisions` | paired identity and separation of individual and aggregate evidence | estimand, number of conditions, scale policy, reference line, interval convention |
| Risk/forecast calibration or two outcomes sharing a prediction | `templates/icbr/fig3_risk_forecasts` | shared actual-error coordinate, paired marks, separate score/mean panel | metric names, transformations, limits, symbols |
| Mechanism or factor decomposition across a row | `templates/robotsoft/mechanism_compact` | four-panel rhythm, interval rows, stable factor colour roles | number of mechanisms, row labels, uncertainty and control semantics |
| Allocation policy or design-budget comparison | `templates/robotsoft/fifth_compact` or `endpoint_compact` | distribution strip plus effect/interval companion | policy names, independent unit, grouping rules, axis scale |
| Structure robustness or sensitivity across settings | `templates/robotsoft/structure_robustness` or `templates/icbr/figS2_matched_conditions` | repeated settings, shared panel tracks, reference/zero lines | factor hierarchy and completeness of conditions |
| Repeated measurements over time or conditions | `templates/icbr/figS2_matched_conditions` or selected RobotSoft trajectory elements | repeated-label alignment and a clear time/condition reading order | model, uncertainty, treatment identity, visit structure, and whether individual trajectories belong |
| Physical/trajectory/robot result | `templates/robotsoft/arm_results` | synchronized traces, key state markers, restrained annotation | physical variables, coordinate conventions, example selection |
| Graphical abstract | `templates/icbr/graphical_abstract` | visual hierarchy, node/arrow/icon grammar, short evidence frames | all science-specific icons, claims, effects, and reading order |

## How much to borrow

- **Whole composition:** only when its evidence arrangement genuinely fits the new question.
- **One motif:** borrow a useful interval row, strip, identity line, node/arrow treatment, or direct label.
- **Visual reference only:** use to judge hierarchy, spacing, or tone; do not inherit its scientific metaphor by default.
- **Nothing:** start fresh when a bundled example does not fit.

No need to announce a template level to the user. Keep only what reduces work without making the new figure read like the old study.

## Examples in this package

- RobotSoft formal figures: `templates/robotsoft/endpoint_compact.*`, `mechanism_compact.*`, `fifth_compact.*`, `structure_robustness.*`, and `arm_results.*`, with `render_compact_figures.py` as the source pattern.
- ICBR/research-craft formal figures: `templates/icbr/fig1_data_overview.*` through `fig4_model_extension.*`, `figS1`–`figS5`, and `render_figures.py`.
- Graphical abstract: `templates/icbr/graphical_abstract.*` and `make_graphical_abstract.py`. The network/node/arrow/icon treatment is a reference for schematic assets; the actual visual relations must be redrawn from the new project's evidence.
- Neutral layout smoke test: `templates/template_multipanel.*` generated by `scripts/template_multipanel.py`. It is deliberately data-independent and tests cross-panel alignment and text QA.

## What to extract from a template

Extract the reusable design decision, not the surface:

1. What is the reading order?
2. Which object is primary, and which is context or control?
3. Are comparable quantities on common axes?
4. Which repeated labels share a left edge, baseline, or numeric column?
5. Which colours encode roles and which only support hierarchy?
6. Which elements need shape/fill/line redundancy?
7. Which text/line/mark clearances remain at final size?

For a substantial redesign, record important adaptations and compare against the original when available. A small exploratory sketch need not create a manifest.
